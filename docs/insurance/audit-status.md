**최종 갱신:** 2026-09-03 · **기준:** 현재 `main`

2026-08-24 감사에서 제기된 Critical/High/Medium/Low 항목은 **전부 닫혔다.** 이 문서는
저장소만으로 결정 과정을 이해할 수 있도록 남긴 **감사 항목의 상태 기록**이며, 항목 상태의
최종 판정은 여기를 따른다. 저장소 전체의 진입점은 루트 `README.md` 하나이며, 이 문서는
그 아래의 상태 기록이지 색인이 아니다.

### 계산 개통 상태

**5세대 급여 통원은 개통 완료다.** 사용자가 건강보험 본인부담률을 입력한 경우 계산하며,
미입력 시 계산에 필요한 입력을 요청한다. 미입력 시의 `PENDING_UNVERIFIED`는 근거 부재로 인한
HOLD가 아니라 **정상적인 입력 검증**이다.
근거: `src/lib/insurance/engine/generation2026.ts`, `tests/generation2026.test.ts`
(건보율 40% 입력 시 계산 / 미제공 시 입력 요청, 양쪽 모두 테스트로 고정).

> **오탐 기록** 감사 과정에서 문자열 grep만으로 미해결 판정을 내릴 뻔한 항목이 4건 있었다
> (타입 union의 잔존 이름, 공유 컴포넌트에 위치한 JSON-LD, 다른 문맥의 "소멸"). 실제 코드를
> 열어 확인한 뒤 전부 오탐으로 확정했다. **얕은 신호로 판정하지 않는다.**

## 2. 설계 원칙 — 이 저장소가 지키는 것

1. **근거 없는 상수를 넣지 않는다.** 모든 규제 상수는 `regulatoryRules.ts`에 문서명·발행기관·
   시행일·URL·조항 위치와 함께 등록되며, 이를 만족하지 않으면 `tests/regulatoryRules.test.ts`가
   빌드를 막는다.
2. **모르는 것은 모른다고 표시한다.** 근거가 확정되지 않은 경로는 값을 지어내지 않고
   `PENDING_UNVERIFIED`를 반환한다(`status: "HOLD"`, `value: null`).
3. **사실을 단정하는 UI 문구를 가드한다.** `tests/uiCopy.test.ts`가 근거 없는 단정이
   되돌아오는 것을 **양방향으로** 막는다(역년 단정도, 계약해당일 단정도).
4. **불변식과 도달 가능성을 검사한다.** 상수만 검증해서는 C-1·C-2 유형의 결함이 잡히지 않는다.
5. **사용자 사실값을 추정으로 대체하지 않는다.** 표준형/선택형처럼 계약이 정하는 값은
   날짜로 추정하지 않고 입력받는다.

### 3.3 별표15 2026.8.28 현행본 대조 범위 (2026-09-03)

현행본은 [금융감독원세칙, 2026. 8. 28.]이고, 이 저장소의 5세대 규칙은 2026.5.6 연혁본을 근거로
등록돼 있다. **직접 눈으로 대조한 조문은 아래뿐이다.**

- 특별약관1 제3조 (1)상해비급여 / (2)질병비급여 / (3)3대비급여 — 인쇄 p.259~265
- 특별약관1 제5조(보험가입금액 한도 등) ①②③④⑤ — 인쇄 p.280~281
- 특별약관2 제3조 (1)상해비급여 / (3)비급여 자기공명영상진단 — 인쇄 p.288, p.294~295
- 특별약관2 제5조 ① — 인쇄 p.309

위 조문은 **문언이 동일**했고 인쇄 쪽수만 1쪽씩 뒤로 밀렸다(연혁본 p.280 → 현행본 p.281).

**대조하지 않은 조문까지 "5세대 약관 전체가 무변경"이라고 확대 해석하지 않는다.** 그래서 기존
규칙의 검증일·쪽수·출처를 현행본으로 일괄 교체하지 않았다. 교체하려면 해당 조문을 실제로 읽고
규칙 단위로 갱신해야 한다.
